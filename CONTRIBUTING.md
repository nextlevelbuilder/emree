# Contributing to Emree

Design/pre-alpha. Start with [DECISIONS.md](DECISIONS.md), [PRD](docs/PRD.md) and [implementation plan](plans/IMPLEMENTATION.md). Propose changes with the problem, alternative, smallest useful scope, security boundary, acceptance criteria and test plan. Keep PRs focused and document contract changes. No implementation/build instructions yet because the app has not been scaffolded.

Contribute only material you have rights to license under Apache-2.0; retain applicable upstream notices. No copied restricted code, secrets, customer data, production topology or private artifacts. Use mock data for UI examples. Review dependencies and licenses; propose executable plugin capabilities only with explicit threat model. Security reports follow [SECURITY.md](SECURITY.md). Before first external code contribution, maintainers should confirm contributor policy (DCO or CLA) and enable branch protection/required reviews. Do not claim a feature works without test evidence.
