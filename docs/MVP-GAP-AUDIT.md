# MVP gap audit and delivery decisions

Date: 2026-11-27. Reviewed Emree main 270688863fb44da42b300f220a2c6ae32516d7ac (design-only), Dewee default-branch snapshot 308e1ba899a5e1ad124820aec8e7b3b0870aead1 and relevant issue records. This is a document/targeted-source review, not a running app, security audit or exhaustive production verification. No existing feature is assumed deployed based on a document or issue. Re-check the current upstream branch and live capabilities before implementation.

## Executive finding

v0.6 covers architecture and broad product requirements well, but its first alpha gate bundles onboarding, native rooms, media, extension registry and modern MCP. The gap is delivery granularity, executable cross-repo contracts and evidence, not another subsystem. Keep PRD R01–R49, D01–D20 and ADRs as target scope; [MVP roadmap](../plans/MVP.md) supersedes phase ordering for the initial pilot only. Each completed gate must be independently usable or explicitly an internal spike; don't present a mock as a working product. Use the existing Dewee agent conversation as first real value before native room or MCP migration.

## First decisions to lock in G0

- Define canonical contract authority, exact reference OS/versions and staging fixture owners, release channel and rollback policy. No public production or secret changes as part of design.
- Establish first pilot cohort and accepted-task metric, minimum demo and evidence per gate. Prefer reuse of existing Dewee surfaces; do not create a second gateway, task manager, auth engine, plugin marketplace or UI protocol.
- Keep all prior scope in PRD. Only first-release sequencing changes. Additional UX polish, full modern MCP/extension conformance and vendor overlays, multi-platform support, shared DevBox, Computer Use and live federation require separate gates.
- Treat open upstream security issues as reported findings until independently verified; audit their reachability, block affected capabilities, no claim about deployed exploitability.

See [MVP roadmap](../plans/MVP.md) for milestones and dependency order.
